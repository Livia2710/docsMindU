Como usar esta página

Clique em uma rota para ver um resumo. O botão Abrir guia detalhado leva a uma página própria com pré-requisitos, passos, campos, autenticação, respostas, erros comuns e exemplos para React e Android. Use o seletor Local / Web no topo para trocar o endereço em todos os exemplos.

Local: http://localhost:8080 — precisa do backend rodando no computador (copie .env.example para .env e execute docker compose -f docker-compose.local.yml up --build; veja o tutorial).
Web: https://mindu-api.onrender.com — o Render pode entrar em cold start; a primeira requisição após inatividade pode levar aproximadamente 1 minuto.

Toda rota, exceto as marcadas público, exige o cabeçalho Authorization: Bearer <token>, obtido no login. Erros, inclusive 401 (não autenticado) e 403 (sem permissão), retornam JSON com erro, por exemplo {"erro":"Não autenticado ou token inválido/expirado","status":401}. Validações incluem campos, por exemplo {"erro":"Erro de validação","campos":{"email":"Formato inválido"},"status":400}.
Status documentados: 400 validação/requisição, 401 autenticação, 403 autorização, 404 não encontrado, 409 conflito, 413 upload grande, 429 limite de login (header Retry-After) e 502 integração indisponível.

Importante sobre o login: POST /v1/auth/login normaliza o e-mail com trim e minúsculas, portanto maiúsculas/minúsculas não fazem diferença. Retorna apenas token e tipo; o JWT expira em 1 hora e não há refresh token. Depois de salvar o token, chame GET /v1/auth/me para receber id, nome e email. Use rotas /me quando disponíveis. Limite padrão: 10 tentativas de login por minuto por IP; excedê-lo retorna 429 com Retry-After, header exposto via CORS para leitura no JavaScript. Para sair ou ao receber 401, apague o token e redirecione para o login.

Configuração inicial

Um helper único que já resolve a URL e o token. Crie em src/api.js:

const BASE_URL = "http://localhost:8080"; // troque para a URL Web ao publicar

export function getToken() {
  return localStorage.getItem("mindu_token");
}

export async function api(path, { method = "GET", body, isFormData = false, onResponse } = {}) {
  const headers = {};
  const token = getToken();
  if (token) headers["Authorization"] = `Bearer ${token}`;
  if (!isFormData) headers["Content-Type"] = "application/json";

  const res = await fetch(`${BASE_URL}${path}`, {
    method,
    headers,
    body: isFormData ? body : body ? JSON.stringify(body) : undefined,
  });
  if (onResponse) onResponse(res); // permite ler Retry-After e headers de paginação

  if (!res.ok) {
    const erro = await res.json().catch(() => ({}));
    if (res.status === 401) {
      localStorage.removeItem("mindu_token");
      window.location.assign("/login"); // ajuste à rota de login do seu front
    }
    if (res.status === 403) throw new Error(erro.erro || "Sem permissão para este recurso");
    throw new Error(erro.erro || erro.message || `Erro ${res.status}`);
  }
  return res.status === 204 ? null : res.json();
}

// Nas respostas do Admin, estes headers de paginação estão expostos via CORS.
export async function carregarPaginaProfissionais() {
  let pagina;
  const profissionais = await api("/v1/admin/profissionais?page=0&size=20", {
    onResponse: resposta => pagina = {
      total: Number(resposta.headers.get("X-Total-Count")),
      page: Number(resposta.headers.get("X-Page")),
      pageSize: Number(resposta.headers.get("X-Page-Size")),
      totalPages: Number(resposta.headers.get("X-Total-Pages")),
    }
  });
  return { profissionais, pagina };
}

RetrofitClient.java — monta o cliente e injeta o token salvo:

public class RetrofitClient {
    private static final String BASE_URL = "http://10.0.2.2:8080/"; // emulador -> localhost da máquina
    private static Retrofit retrofit;

    public static SharedPreferences getSecurePreferences(Context context) {
        try {
            MasterKey key = new MasterKey.Builder(context).setKeyScheme(MasterKey.KeyScheme.AES256_GCM).build();
            return EncryptedSharedPreferences.create("mindu_secure", key, context,
                EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
                EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM);
        } catch (Exception e) { throw new IllegalStateException("Não foi possível abrir o armazenamento seguro", e); }
    }

    public static Retrofit getInstance(Context context) {
        if (retrofit == null) {
            OkHttpClient client = new OkHttpClient.Builder()
                .addInterceptor(chain -> {
                    SharedPreferences securePrefs = getSecurePreferences(context);
                    String token = securePrefs.getString("token", null);
                    Request.Builder b = chain.request().newBuilder();
                    if (token != null) b.addHeader("Authorization", "Bearer " + token);
                    Response response = chain.proceed(b.build());
                    if (response.code() == 401) securePrefs.edit().remove("token").apply();
                    // A camada de tela redireciona ao login no 401; no 403, informa falta de permissão.
                    return response;
                })
                .addInterceptor(new HttpLoggingInterceptor().setLevel(BuildConfig.DEBUG ? HttpLoggingInterceptor.Level.BASIC : HttpLoggingInterceptor.Level.NONE))
                .build();

            retrofit = new Retrofit.Builder()
                .baseUrl(BASE_URL)
                .client(client)
                .addConverterFactory(GsonConverterFactory.create())
                .build();
        }
        return retrofit;
    }
}

No emulador Android, use a base URL http://10.0.2.2:8080/; localhost aponta para o próprio emulador. Android 9 ou posterior costuma bloquear HTTP sem TLS: configure um network security config no app para liberar HTTP somente para 10.0.2.2 e apenas no build de debug. Essa configuração pertence ao repositório Android, não a esta API. Em produção use HTTPS (https://mindu-api.onrender.com).

Guarde o JWT em EncryptedSharedPreferences; ele expira em 1 hora e não há refresh token. Ao receber 401, remova o token e encaminhe a pessoa ao login; no 403, mantenha a sessão e informe que o recurso não é permitido.
