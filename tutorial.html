Guia de desenvolvimento

Rodar a API localmente

O Docker inicia o backend Spring Boot e o PostgreSQL no computador de cada pessoa. Sabrina e Manoela podem usar a mesma API; muda apenas o endereço que o React ou o Android usa para chamá-la.

Exibindo as instruções específicas da Sabrina. As etapas comuns ficam visíveis para ambas.

Os comandos de terminal desta página são para o Prompt de Comando do Windows (cmd.exe). Abra o menu Iniciar, digite cmd e escolha Prompt de Comando. Não cole esses comandos no PowerShell. Use o botão Copiar para copiar cada bloco.
O que fica local?

A API responde em http://localhost:8080 no computador que roda o Docker. O banco local é separado do banco do Render: os dados de produção não são copiados.

1. Preparação (uma vez por computador)

  1. Instale o Docker Desktop para Windows. Se o instalador pedir, habilite o WSL 2 e reinicie o computador. Consulte os requisitos e passos oficiais para Windows.
  2. Instale o Git for Windows para clonar os repositórios.
  3. Inicie o Docker Desktop e espere ele indicar que está em execução.

Não é necessário instalar Java, Maven ou PostgreSQL separadamente para rodar o backend pelo Docker.

Para iniciar o React, Sabrina também precisa do Node.js.

Para o app, Manoela usa o JDK e as ferramentas instaladas pelo Android Studio.

2. Clonar e iniciar a API e o banco

No cmd.exe, clone o repositório do backend. A conta precisa ter acesso ao repositório:


git clone https://github.com/Livia2710/javaMindU.git
cd javaMindU

Na pasta javaMindU, construa a imagem da API e inicie os dois serviços:

docker compose -f docker-compose.local.yml up --build

Na primeira execução, o Docker baixa as imagens e compila o backend, então pode demorar. Deixe o terminal aberto para acompanhar os logs. Quando a API iniciar, estará em http://localhost:8080.

Para deixar os containers em segundo plano, use -d e acompanhe os logs da API com o segundo comando:

docker compose -f docker-compose.local.yml up --build -d
docker compose -f docker-compose.local.yml logs -f api

Para parar a API e o banco sem apagar os dados locais, pressione Ctrl+C no terminal em primeiro plano ou execute:

docker compose -f docker-compose.local.yml down

3. Confirmar que a API está respondendo

Com os containers ativos, abra outra janela do cmd.exe e faça uma chamada para um endpoint público:

curl.exe http://localhost:8080/v1/planos

A resposta aparecerá no cmd.exe, e a requisição também aparecerá nos logs da API. Se os planos ainda não tiverem sido cadastrados no banco local, uma lista vazia pode ser normal; isso não significa, por si só, que a conexão falhou.

Banco local

O banco local começa separado e não contém os dados do Render. Use dados fictícios para os testes. O volume Docker mantém os dados locais entre inicializações.

4. Sabrina — conectar o React local à API

  1. Instale as dependências e configure o endereço da API.

No arquivo src/api.js, Sabrina deve ler a URL de uma variável do Vite, mantendo Render como padrão para os outros ambientes:

const BASE_URL =
  import.meta.env.VITE_API_BASE_URL ||
  "https://mindu-api.onrender.com";

Crie .env.local na pasta FrondEnd/mindU:

VITE_API_BASE_URL=http://localhost:8080
npm install
npm run dev

Abra http://localhost:5173. Se o arquivo .env.local mudar enquanto o Vite estiver ativo, pare e inicie o Vite novamente. Não envie o arquivo .env.local ao GitHub.

A API já permite a origem local do Vite (http://localhost:5173) no CORS.

5. Manoela — conectar o Android Studio à API

Manoela inicia o backend com os mesmos comandos Docker da seção 2, no computador onde ela também executa o Android Studio. No app Android, localize a configuração do cliente HTTP — por exemplo, BASE_URL, Retrofit.Builder ou BuildConfig — e use:

http://10.0.2.2:8080/

No emulador Android, 10.0.2.2 é o endereço especial que alcança o loopback do computador anfitrião. localhost dentro do app apontaria para o próprio emulador. Veja a documentação de rede do emulador.

O app Android nativo não usa CORS como o React no navegador. Se o Android bloquear a chamada HTTP local, habilite tráfego HTTP somente na configuração de desenvolvimento/debug do app; não relaxe essa configuração na versão de produção. Consulte a documentação Android sobre Network Security Configuration.

Sem abrir o emulador

Manoela pode iniciar a API e confirmar uma chamada pelo cmd.exe, como na seção 3. Isso verifica a API e o banco, mas não testa a conexão feita pelo app Android. Para validar o app de ponta a ponta, será necessário executá-lo em um emulador ou dispositivo Android.

Problemas comuns

  • Docker não inicia: abra o Docker Desktop, aguarde ficar pronto e confira se o WSL 2 foi habilitado quando solicitado.
  • Porta 8080 ocupada: feche o outro serviço que a utiliza antes de iniciar o Compose.
  • React continua chamando Render: confira o valor em .env.local e reinicie npm run dev.
  • Android não conecta usando localhost: no emulador, use 10.0.2.2 para alcançar a máquina anfitriã.
  • Android informa que HTTP sem criptografia não é permitido: libere HTTP somente para debug/desenvolvimento.
  • Precisa conferir os logs: no cmd.exe, execute docker compose -f docker-compose.local.yml logs -f api.

O arquivo docker-compose.local.yml e a atualização do Dockerfile precisam estar commitados e disponíveis no repositório do backend antes de Sabrina ou Manoela clonarem uma cópia nova.
