Guia de desenvolvimento

Rodar a API localmente

O Docker inicia o backend Spring Boot, o PostgreSQL e o serviço interno da Mila no computador de cada pessoa. Sabrina e Manoela acessam o chat pela API Java; cada uma conecta seu próprio front-end a ela.

Mostrar instruções de:

Exibindo as instruções específicas da Sabrina. As etapas comuns ficam visíveis para ambas.

Os comandos de terminal desta página são para o Prompt de Comando do Windows (cmd.exe). Abra o menu Iniciar, digite cmd e escolha Prompt de Comando. Não cole esses comandos no PowerShell. Use o botão Copiar para copiar cada bloco.
O que fica local?

A API responde em http://localhost:8080 no computador que roda o Docker. O banco local é separado do banco do Render: os dados de produção não são copiados.

1. Preparação (uma vez por computador)

  1. Instale o Docker Desktop para Windows. Se o instalador pedir, habilite o WSL 2 e reinicie o computador. Consulte os requisitos e passos oficiais para Windows.
  2. Instale o Git for Windows para clonar os repositórios.
  3. Inicie o Docker Desktop e espere ele indicar que está em execução.

Não é necessário instalar Java, Maven ou PostgreSQL separadamente para rodar o backend pelo Docker.

Para iniciar o React, Sabrina também precisa do Node.js.

Para o app, Manoela usa o JDK e as ferramentas instaladas pelo Android Studio.

2. Clonar e iniciar a API e o banco

Vamos configurar o computador para que o Docker consiga construir os três serviços necessários: PostgreSQL, API Java e API interna da Mila. A interface do site e o app Android chamam somente o Java.

2.1 Abrir o Prompt de Comando

  1. Pressione a tecla Windows, digite cmd e abra Prompt de Comando. Esta página usa comandos para o CMD, não para o PowerShell.
  2. Os comandos devem ser colados na janela preta do CMD e executados com Enter. Copie um bloco inteiro por vez.
  3. Confirme que o Docker Desktop está aberto e indica que está em execução.

2.2 Clonar os dois projetos

“Clonar” significa baixar uma cópia do repositório para o computador. Os dois projetos precisam ficar dentro da mesma pasta GitHub. Se essa pasta não existir, crie-a primeiro pelo Explorador de Arquivos em Documentos. No CMD, execute estas linhas, uma por vez:

cd /d "%USERPROFILE%\Documents\GitHub"
git clone https://github.com/Livia2710/javaMindU.git
git clone https://github.com/Livia2710/mila.git Mila
cd javaMindU

Se o GitHub pedir autenticação ou disser que você não tem acesso, entre na conta autorizada; se o repositório estiver privado, a responsável precisa primeiro convidar seu usuário. Ao terminar, existem duas pastas irmãs: javaMindU e Mila. O Compose precisa dessa posição para encontrar os arquivos.

2.3 Entender o que é .env

Um arquivo .env é um bloco de notas simples que guarda configurações usadas pelos programas quando iniciam. Cada linha tem o formato NOME_DA_CONFIGURACAO=valor. Não coloque espaços ao redor do sinal = e não publique esses arquivos no GitHub. As senhas e chaves ficam nos computadores/servidores, não no código-fonte.

NomePara que serveOnde fica
GROQ_API_KEYCredencial do provedor que a Mila usa para gerar respostas e transcrever áudio. É fornecida por quem administra o acesso Groq; não é criada pelo Java.Só em Mila\.env.
MILA_API_KEYSenha interna compartilhada entre Java e Mila para o Java autenticar chamadas ao serviço Mila. Não é a chave Groq. Cada pessoa pode gerar uma chave local e colocar o mesmo valor nos dois arquivos.Nos dois arquivos: javaMindU\.env e Mila\.env.
MINDU_ADMIN_SENHASenha local dos usuários administradores de teste do banco MindU. Use a senha local fornecida pela responsável pelo backend.Só em javaMindU\.env.

2.4 Criar o arquivo de configuração da Mila

Primeiro entre na pasta da Mila e copie o modelo de configuração que já vem no projeto:

cd ..\Mila
copy .env.example .env
notepad .env

Como este é um clone novo, normalmente ainda não haverá um .env. Se o CMD perguntar se deseja sobrescrever um .env existente, responda N e abra o arquivo existente no Bloco de Notas para editá-lo. No arquivo aberto, procure GROQ_API_KEY= e substitua o texto de exemplo pela chave Groq fornecida pela responsável. Essa credencial permite que a Mila use o provedor para gerar respostas e transcrever áudio. Não a envie às colegas por um canal público. Salve com Ctrl+S e feche o Bloco de Notas.

Para criar a chave interna local, cole este comando na mesma janela do CMD e copie o texto hexadecimal que aparecer. Embora o comando use uma ferramenta do Windows chamada PowerShell por dentro, você não precisa abrir outra janela:

powershell -NoProfile -Command "[guid]::NewGuid().ToString('N')"

Essa chave aleatória é apenas uma senha interna para a comunicação local Java–Mila; ela não é uma chave de provedor e não tem relação com a conta Groq. Depois de copiá-la do CMD, reabra o arquivo da Mila:

notepad .env

Substitua o valor depois de MILA_API_KEY= pelo texto recém-gerado. Salve com Ctrl+S e feche o Bloco de Notas. Mantenha o valor copiado para colá-lo também no arquivo Java no próximo passo.

2.5 Criar o arquivo de configuração do Java

Agora volte à pasta do backend e abra o arquivo local:

cd ..\javaMindU
notepad .env

Se o Bloco de Notas perguntar se deseja criar o arquivo, escolha Sim. Se ele já existir, não apague as configurações que já estão lá: acrescente ou atualize as linhas abaixo. Em MINDU_ADMIN_SENHA, preserve a senha local que você recebeu. Em MILA_API_KEY, cole exatamente a mesma chave interna que colocou no arquivo da Mila. Se o valor mudar em um dos arquivos, atualize também o outro para que os dois coincidam.

MINDU_ADMIN_SENHA=SENHA_LOCAL_FORNECIDA_PELA_RESPONSAVEL
MILA_BUILD_CONTEXT=../Mila
MILA_ENV_FILE=../Mila/.env
MILA_API_KEY=COLE_A_CHAVE_INTERNA_GERADA

As duas linhas MILA_BUILD_CONTEXT e MILA_ENV_FILE dizem ao Docker onde encontrar, respectivamente, o código da Mila e o arquivo de configurações dela. Salve com Ctrl+S e feche o Bloco de Notas.

Confira o nome do arquivo antes de continuar

Os nomes devem ser exatamente .env, sem .txt. Se o Bloco de Notas abrir a janela “Salvar como”, escolha Todos os arquivos no tipo e digite ".env" no nome do arquivo. Não compartilhe uma captura de tela que mostre valores de chaves. Os arquivos .env são ignorados pelo Git; os modelos .env.example podem ser publicados porque não contêm credenciais reais.

2.6 Construir e iniciar Java, banco e Mila

Volte a confirmar que o CMD está dentro da pasta javaMindU. Agora execute:

docker compose -f docker-compose.local.yml up --build -d api db mila

Na primeira vez pode demorar: o Docker baixa dependências, prepara os documentos da base de conhecimento e constrói os serviços. O parâmetro -d deixa os serviços em segundo plano. Quando terminar, o Java estará em http://localhost:8080; a Mila é interna e o front não chama sua porta diretamente. Se aparecer erro dizendo que GROQ_API_KEY está vazia/ausente, volte ao arquivo Mila\.env, preencha essa chave e rode o comando novamente.

Para conferir se os três serviços iniciaram, execute:

docker compose -f docker-compose.local.yml ps

Para ver os logs enquanto investigam um erro, execute:

docker compose -f docker-compose.local.yml logs -f api mila

Pressione Ctrl+C para parar somente a exibição dos logs. Os containers continuam ligados. Para desligá-los sem apagar os dados locais do banco:

docker compose -f docker-compose.local.yml down

3. Confirmar que a API está respondendo

Com os containers ativos, abra outra janela do cmd.exe e faça uma chamada para um endpoint público:

curl.exe http://localhost:8080/v1/planos

A resposta aparecerá no cmd.exe, e a requisição também aparecerá nos logs da API. Se os planos ainda não tiverem sido cadastrados no banco local, uma lista vazia pode ser normal; isso não significa, por si só, que a conexão falhou.

Para consultar diretamente o PostgreSQL, abra o cliente psql que já vem no container do banco:

docker compose -f docker-compose.local.yml exec db psql -U postgres -d mindu

Dentro do psql, liste as tabelas e consulte os planos e admins:

\dt
SELECT nome, vagas_totais, porte_indicado FROM plano ORDER BY nome;
SELECT u.nome, u.email FROM usuario u JOIN admin a ON a.id = u.id ORDER BY u.nome;
\q

\q sai do psql. As tabelas aparecem depois que a API inicia e cria o schema.

Banco local

O banco local começa separado e não contém os dados do Render. Use dados fictícios para os testes. O volume Docker mantém os dados locais entre inicializações.

4. Como o chat chega à Mila

O app/site manda a mensagem para o Java com o JWT do usuário. O Java valida esse token e encaminha a mensagem à Mila usando uma chave interna guardada no ambiente dos servidores. A resposta volta pelo Java para o front. O React e o Android nunca recebem nem enviam a chave interna ou a chave Groq.

  1. Faça login pela API e guarde o JWT como já é feito nas outras telas.
  2. Envie cada mensagem para POST /v1/chat, com Authorization: Bearer <JWT>.
  3. Envie message e history em JSON. A mensagem pode ter até 4.000 caracteres; o histórico pode ter até 20 turnos com papel user ou assistant.
  4. Mostre o campo response da resposta no balão da Mila. Acrescente a pergunta e a resposta ao histórico local e envie-o na próxima chamada. A Mila não mantém histórico entre chamadas nem grava a conversa; se o app não reenviar o histórico, ela não lembrará mensagens anteriores.
{
  "message": "O que é o MindU e o que a Mila pode me ajudar a fazer?",
  "history": []
}
{
  "response": "...texto da resposta da Mila...",
  "intent": "sobre_mindu",
  "sources": [],
  "missing_info": false,
  "debug_info": {},
  "transcription": null
}

O campo debug_info é técnico e não deve ser exibido como mensagem ao usuário. A resposta pode conter emojis ou Markdown. Renderizem texto/Markdown com uma biblioteca segura; não insiram a resposta como HTML bruto (innerHTML), pois conteúdo vindo de um modelo não deve ser tratado como código confiável.

Áudio e arquivos

Áudio é enviado como multipart/form-data para POST /v1/chat/audio; o retorno inclui a transcrição. A Mila aceita formatos de áudio configurados no serviço, com limite local padrão de 10 MB. Imagens e PDFs não são suportados nesta rota; a Mila informa isso na resposta. Não envie áudio como JSON/base64. No navegador, não defina manualmente o cabeçalho multipart: deixe o FormData criar o boundary.

Antes de conectar a interface, testem a rota no Postman ou no terminal com um JWT real. A resposta 401 indica token ausente/inválido; 502 normalmente indica que o Java não alcançou a Mila ou que ela falhou. Para ver os logs dos dois serviços, use:

docker compose -f docker-compose.local.yml logs -f api mila

5. Sabrina — conectar o React local à API

  1. Instale as dependências e configure o endereço da API.

No arquivo src/api.js, Sabrina deve ler a URL de uma variável do Vite, mantendo Render como padrão para os outros ambientes:

const BASE_URL =
  import.meta.env.VITE_API_BASE_URL ||
  "https://mindu-api.onrender.com";

Crie .env.local na pasta FrondEnd/mindU:

VITE_API_BASE_URL=http://localhost:8080
npm install
npm run dev

Abra http://localhost:5173. O CMD que executa npm run dev precisa continuar aberto enquanto Sabrina usar o site. Se o arquivo .env.local mudar enquanto o Vite estiver ativo, pare e inicie o Vite novamente. Não envie o arquivo .env.local ao GitHub.

A API já permite a origem local do Vite (http://localhost:5173) no CORS.

Exemplo de envio de texto no componente do chat (considerando que api já anexa o JWT):

const resultado = await api("/v1/chat", {
  method: "POST",
  body: { message: texto, history }
});
adicionarMensagemMila(resultado.response);

Para voz, grave ou selecione um arquivo de áudio e envie um FormData para /v1/chat/audio, com as partes file, message (opcional) e history (string JSON). O JWT segue no cabeçalho Authorization. Não configure Content-Type manualmente.

6. Manoela — conectar o Android Studio à API

Manoela inicia o backend com os mesmos comandos Docker da seção 2, no computador onde ela também executa o Android Studio. No app Android, localize a configuração do cliente HTTP — por exemplo, BASE_URL, Retrofit.Builder ou BuildConfig — e use:

http://10.0.2.2:8080/

No emulador Android, 10.0.2.2 é o endereço especial que alcança o loopback do computador anfitrião. localhost dentro do app apontaria para o próprio emulador. Veja a documentação de rede do emulador.

O app Android nativo não usa CORS como o React no navegador. Se o Android bloquear a chamada HTTP local, habilite tráfego HTTP somente na configuração de desenvolvimento/debug do app; não relaxe essa configuração na versão de produção. Consulte a documentação Android sobre Network Security Configuration.

Sem abrir o emulador

Manoela pode iniciar a API em segundo plano e fechar o CMD, como na seção 2. Docker Desktop e computador precisam continuar ligados. Ela pode confirmar uma chamada pelo cmd.exe, como na seção 3; isso verifica a API e o banco, mas não testa a conexão feita pelo app Android. Para validar o app de ponta a ponta, será necessário executá-lo em um emulador ou dispositivo Android.

Crie uma chamada Retrofit autenticada para POST v1/chat, com um DTO contendo message e a lista history. O interceptor que já adiciona o JWT nas outras chamadas também deve protegê-la. Para áudio, use @Multipart e envie as partes file, message (opcional) e history como string JSON; não coloque a chave da Mila no app.

Problemas comuns

  • Docker não inicia: abra o Docker Desktop, aguarde ficar pronto e confira se o WSL 2 foi habilitado quando solicitado.
  • Porta 8080 ocupada: feche o outro serviço que a utiliza antes de iniciar o Compose.
  • React continua chamando Render: confira o valor em .env.local e reinicie npm run dev.
  • Android não conecta usando localhost: no emulador, use 10.0.2.2 para alcançar a máquina anfitriã.
  • Android informa que HTTP sem criptografia não é permitido: libere HTTP somente para debug/desenvolvimento.
  • Precisa conferir os logs: no cmd.exe, execute docker compose -f docker-compose.local.yml logs -f api.

Para usar o chat local, ambas precisam ter acesso ao repositório da API Java e ao repositório separado da Mila. O Compose monta a imagem da Mila a partir do código local em cada computador.
