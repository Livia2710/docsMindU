Como integrar a Mila no chat

Este guia explica o que a Mila já faz, o que ainda não suporta e como o front deve enviar texto, manter o histórico da conversa e mandar áudio. O front chama sempre a API Java; não chama o serviço interno da Mila diretamente.

1. O caminho de uma mensagem

  1. A pessoa entra no MindU e o app/site obtém um JWT pelo login normal.
  2. O front envia a mensagem para o Java com Authorization: Bearer <JWT>.
  3. O Java valida a conta e encaminha o conteúdo para a API interna da Mila.
  4. A Mila devolve uma resposta; o Java a devolve ao front.

Use POST /v1/chat para texto e POST /v1/chat/audio para áudio. Não coloque GROQ_API_KEY nem MILA_API_KEY no projeto React, no APK, no Postman compartilhado ou no armazenamento do navegador/celular. O JWT do usuário é o único token que o front envia.

2. O que está disponível hoje

RecursoEstado atualO que o front faz

PDFs da base de conhecimento são outra coisa: os documentos preparados pela equipe são usados no RAG do serviço Mila. Isso não significa que a pessoa possa anexar um PDF à conversa. Ler anexos enviados pelo usuário exigiria uma funcionalidade nova no backend.

3. Fazer o histórico funcionar

A Mila não possui memória própria entre requisições e o Java não persiste mensagens. “Lembrar” durante uma conversa é responsabilidade do front: ele guarda os turnos e reenvia os anteriores junto com a nova mensagem. Cada turno tem role (user ou assistant) e content. A requisição aceita até 20 turnos; por padrão, a Mila usa os últimos 8 na geração da resposta.

Exemplo: ao enviar “E quanto custa?”, o front deve incluir no histórico a pergunta e a resposta anteriores que dão contexto. A mensagem atual vai em message, separada do histórico.

import { useState } from "react";

const [mensagens, setMensagens] = useState([]);

async function enviar(texto) {
  const history = mensagens.map(({ role, content }) => ({ role, content }));
  setMensagens(atual => [...atual, { role: "user", content: texto }]);

  const resultado = await api("/v1/chat", {
    method: "POST",
    body: { message: texto, history }
  });

  setMensagens(atual => [...atual, {
    role: "assistant", content: resultado.response
  }]);
}

No Android, guardem a mesma lista no ViewModel enquanto a tela/conversa estiver aberta. Quando iniciar uma conversa nova, comecem com uma lista vazia. Se quiserem que a conversa sobreviva ao fechamento do app, isso exige armazenamento local adicional, por exemplo Room; combinem esse comportamento antes, pois mensagens podem conter informações pessoais de saúde. A API Java/Mila não recupera o histórico depois.

O front deve enviar no máximo 20 turnos e evitar mandar conversas inteiras muito longas. Cada conteúdo tem limite de 4.000 caracteres; a Mila normalmente usa apenas os últimos 8 turnos, conforme sua configuração.

4. Enviar texto pelo React

A função api da documentação já anexa o JWT salvo no login e serializa o objeto como JSON:

const resposta = await api("/v1/chat", {
  method: "POST",
  body: { message: textoDigitado, history }
});

// Mostrar resposta.response no balão da Mila.
// Não exibir debug_info como mensagem do chat.

A resposta também inclui intent, sources, missing_info, debug_info e transcription. A interface de chat normalmente precisa exibir response; transcription é útil após áudio. debug_info é diagnóstico interno e não deve aparecer para a pessoa.

5. Enviar texto pelo Android (Retrofit)

data class ChatTurn(val role: String, val content: String)
data class ChatRequest(val message: String, val history: List<ChatTurn>)
data class ChatResponse(
    val response: String,
    val intent: String,
    val sources: List<String> = emptyList(),
    val missing_info: Boolean = false,
    val debug_info: Map<String, Any> = emptyMap(),
    val transcription: String? = null
)

interface MinduApi {
    @POST("v1/chat")
    suspend fun enviarMensagem(@Body body: ChatRequest): ChatResponse
}

O interceptor Retrofit que já anexa Authorization: Bearer <JWT> deve atender também essa chamada. Se o app usa Java em vez de Kotlin, os mesmos campos podem ser declarados em classes DTO Java.

6. Como funciona o áudio e a transcrição

O navegador ou o app grava/seleciona o áudio e envia o arquivo para POST /v1/chat/audio. A Mila usa o serviço de transcrição configurado no backend (modelo Whisper via Groq), em português, e depois envia o texto transcrito ao fluxo normal de resposta. A tela não precisa chamar um serviço de transcrição separado.

Formatos aceitos atualmente incluem WebM, OGG, MP3, M4A/MP4, WAV e FLAC, com extensão e MIME compatíveis. O limite padrão é 10 MB. O retorno contém response e transcription. Se a gravação estiver vazia/ininteligível, a resposta informa isso. O funcionamento depende da chave e da disponibilidade do provedor configurado no servidor.

React: enviar arquivo

async function enviarAudio(arquivo, history) {
  const form = new FormData();
  form.append("file", arquivo);
  form.append("history", JSON.stringify(history));

  return api("/v1/chat/audio", {
    method: "POST",
    body: form,
    isFormData: true
  });
}

// O helper mantém o Authorization, mas não define Content-Type.
// O navegador precisa criar o boundary multipart sozinho.

Android: enviar arquivo com Retrofit

interface MinduApi {
    @Multipart
    @POST("v1/chat/audio")
    suspend fun enviarAudio(
        @Part file: MultipartBody.Part,
        @Part("history") historyJson: RequestBody,
        @Part("message") message: RequestBody? = null
    ): ChatResponse
}

O arquivo deve ser uma parte chamada file, com nome e tipo de conteúdo corretos. Envie o histórico como texto JSON, por exemplo [{"role":"user","content":"Oi"}]. O mesmo interceptor deve anexar o JWT. Não envie a chave Groq/Mila no dispositivo.

Quando a resposta chegar, use transcription como texto da mensagem enviada pela pessoa e response como fala da Mila; acrescente os dois turnos ao histórico da tela para a próxima pergunta ter contexto.

7. PDFs e imagens: o que mostrar na tela

A rota de anexo aceita áudio. Se alguém enviar PDF ou imagem para ela, o serviço não extrai texto nem faz OCR/visão: devolve uma resposta amigável dizendo que o formato não é suportado. Para a primeira versão do front, escondam ou desabilitem anexos que não sejam áudio, ou mostrem essa resposta da Mila. Não enviem PDF/imagem esperando que o prompt resolva: o modelo não recebe o conteúdo desses arquivos.

Se a equipe decidir suportar isso futuramente, será uma alteração da API Mila e possivelmente do Java: leitura de PDF/OCR ou análise visual, validação de tipo e tamanho, tratamento de dados e configuração do provedor/modelo apropriado. A interface sozinha não adiciona essa capacidade.

8. Respostas de erro úteis para depuração

  • 401: JWT ausente, inválido ou expirado. Faça login e tente novamente.
  • 413: áudio acima do limite. Reduza o arquivo.
  • 422: corpo, histórico ou arquivo inválido.
  • 502: Java não conseguiu falar com a Mila. Verifiquem os containers e as configurações locais do serviço.
